# A2: quantitative cross-validation of CENOP against DEPONS 3.2

Date: 2026-11-19. Status: bands and scope approved by the user on 2026-11-19, before any
multi-seed run of the disturbed scenario. Committed before those runs were started.
Roadmap: `2026-06-12-cenop-roadmap-design.md`, section A2. Harness: Track A1.

## Why

A2 asks for a committed parity report: CENOP and DEPONS on identical scenarios, at least one
undisturbed and one disturbed, compared statistically, with pass bands fixed before the runs
and a verdict per metric. It is the evidence a reader of the paper needs that CENOP is a
faithful port.

## What exists already (2026-11-19)

Undisturbed Kattegat (v3.2 landscape, 2000 animals), all with eight Java seeds (42-49) and six
CENOP seeds (42-47):

- population at the end of years 1-5, InnerDanishWaters and PSM-Type2;
- population and mean energy through year 1, dispersal off;
- share of animals per 40 km block (two Java seeds);
- dispersal episodes against 200 tracked Java animals (one Java seed).

These were explored without bands declared in advance, so in the report they are labelled
"exploratory, bands applied afterwards". The disturbed scenario has not been run in CENOP with
more than one seed and is the part that can be done properly blind.

## Goals

- One report, regenerated by one command from run outputs, with a verdict per metric.
- A disturbed scenario with bands fixed before any multi-seed CENOP run.
- Enough seeds that a verdict is not an accident: eight per side.

Not goals: tuning CENOP to pass; non-Kattegat landscapes (no DEPONS reference exists for
Lithuania or CentralBaltic); turbines (DEPONS ships no Kattegat turbine scenario; see Open
questions).

Must not happen: a band changed after seeing the result it judges; a comparison of a tracked
sample against a whole population (the cause of two false alarms on 2026-11-19).

## Scenarios

| Id | Mode | Disturbance | Years | Java seeds | CENOP seeds | Status |
|---|---|---|---|---|---|---|
| U-IDW | InnerDanishWaters | none | 5 | 42-49 | 42-49 | CENOP 48, 49 to run |
| U-PSM | PSM-Type2 | none | 5 | 42-49 | 42-49 | CENOP 48, 49 to run |
| U-OFF | off | none | 1 | 42-49 | 42-49 | CENOP 48, 49 to run |
| D-SHIPS | InnerDanishWaters | ships (v3.2 file, 5,148 ships) | 1 | 42-49 | 42-49 | all to run |

D-SHIPS is one year because a CENOP year with ships takes about two hours per seed. Cost:
Java about 12 minutes per seed (measured); CENOP eight seeds in parallel, about two hours.

## Metrics and pass bands

Notation: J and C are the Java and CENOP means over seeds; SE is the standard error of the
difference of means. A metric passes when every listed checkpoint meets its band.

| # | Metric | Scenarios | Checkpoints | Band |
|---|---|---|---|---|
| M1 | Population | all | U: end of each year; U-OFF and D-SHIPS: days 90, 180, 270, 359 | \|C - J\| <= 2 SE, and \|C - J\| <= 10% of J |
| M2 | Population trajectory | all | every day | C within J +/- 2 SD(J) on at least 95% of days |
| M3 | Mean energy (population-wide) | all | days 30, 90, 150, 240, 359 | \|C - J\| <= 2 SE, and <= 0.25 |
| M4 | Where animals are | U-IDW, U-PSM, D-SHIPS | share per block, days 30-360 | total variation distance <= 0.06; correlation >= 0.98 |
| M5 | Age at death | all | whole run | two-sample KS on pooled ages, p > 0.01 |
| M6 | Ship effect on population | D-SHIPS vs U-IDW | day 359 | ratio N(ships) / N(undisturbed): \|C - J\| <= 2 SE |
| M7 | Exposure to ship noise | D-SHIPS | year 1 | share of animal-ticks with ship deterrence > 0: C within 20% of J (Java from its 200 tracked animals per seed while alive; CENOP from all animals) |

Verdict per metric and scenario: PASS, FAIL, or INCONCLUSIVE (band met but SE so large that a
10% difference could not have been detected).

The 2 SE rule alone would pass anything noisy, and the 10% rule alone would fail on noise;
both are required. With eight seeds and the spreads seen so far (SD 3-8 animals at year end),
2 SE is about 4-8% of the mean.

## Deliverables

- `validation/a2/scenarios/*.json` (the four scenarios, seeds 42-49).
- `validation/a2/run_cenop.py` (one CENOP run to a common daily format: population, mean
  energy, animals per block, ship-deterred animal-ticks, ages at death) and
  `validation/a2/report.py` (reads Java and CENOP outputs, writes the report).
- `docs/validation/A2-parity-report.md`: tables, trajectory envelope figures, verdicts, and a
  section on limits (two false alarms, what they taught, what is not covered).
- Tests for the report's statistics on synthetic inputs.

## Decisions (user, 2026-11-19: "follow the recommendations")

1. Bands M1-M7 as written above.
2. No turbine scenario in this report. DEPONS ships no Kattegat turbine scenario, and supplying
   one through its `User-def` file means altering the DEPONS installation. Ships satisfy the
   roadmap's "at least one disturbed scenario". A turbine comparison is a possible follow-up.
3. D-SHIPS runs on the current ship code (bit-identical to the committed ship baseline). A
   faster, not bit-identical ship implementation is a separate item.

## What had been seen before the bands were fixed

For honesty about blinding: all undisturbed results listed under "What exists already", and
for D-SHIPS one seed per side (seed 42: Java 1879 / 239 / 119 / 102 / 99 at days 63 / 180 / 240 /
300 / 359; CENOP 1861 / 244 / 119 / 90 at days 63 / 180 / 240 / 300 from the baseline run in
progress). For exposure (M7), two rough numbers had been seen: one Java tracked animal showed
ship deterrence on 1,609 of 17,280 rows of the year (rows continue after death, so this is a
lower bound on its exposure while alive), and a two-day smoke test of the CENOP runner showed
ship deterrence on 41% and 29% of animal-ticks on days 1 and 2. No multi-seed D-SHIPS result
and no D-SHIPS energy, location or age-at-death number had been seen.
